# HedgeAI 行动计划与完成度评估

## 说明

本文档基于当前代码实际完成情况评估，不按前端/后端拆分，而按产品能力与交付优先级拆分为 P0-P3。

完成度含义：

- 0%-20%：基本未完成或只有占位
- 20%-40%：有雏形，但不可稳定演示或不可真实使用
- 40%-60%：主链路部分可用，但缺关键闭环
- 60%-80%：可用于 Demo 或内测，但仍需加固
- 80%-100%：接近可交付状态

当前整体判断：

- Demo 完成度：约 55%-65%
- MVP 完成度：约 30%-40%
- 实盘产品完成度：约 20%-30%

## P0：Demo 成败关键任务

### P0-1 一键加载 Demo 仓位

当前完成度：85%

当前状态：

- 后端已支持 Injective `demo` 地址返回预置 BTC 高风险仓位。
- 前端聊天标题区已有“加载 Demo 仓位”按钮。
- 点击后会自动连接 Injective demo 账户、同步仓位、刷新风险扫描并写入系统提示。
- Demo 账户被标记为 `mode="demo"`，`trading_enabled=false`。

目标：

任务：

- 点击后自动连接 Injective demo 账户。
- 自动同步仓位到本地状态。

验收标准：

- 无需真实私钥、钱包、交易所账户。

### P0-2 AI 失败兜底策略

当前完成度：80%

当前状态：

- 当前 AI 请求失败后，会基于已连接仓位或风险告警生成三张本地兜底策略卡。
- 兜底策略类型覆盖反向合约、Polymarket 事件市场参考、期权保护参考。
- 兜底输出带 `source="fallback"`、`confidence="local-rule"` 和 `fallback_reason`。
- 无可用仓位时不会凭空生成策略，而是提示先加载 Demo 仓位。
- 策略卡已显示“本地兜底”标签。

目标：

- 即使没有模型 Key 或模型服务不可用，也能完成 Demo。

任务：

- 增加固定 fallback 策略模板。
- fallback 包含三套策略：
  - A：反向合约对冲
  - B：Polymarket 事件对冲参考
  - C：期权保护参考
- AI 失败时自动渲染 fallback 卡片。
- 页面标注“演示策略模板”或“AI 不可用时使用预置方案”。

验收标准：

- 不填 API Key 也能生成三张策略卡。
- 模型请求失败不会中断演示。
- 演示者仍可点击执行或展示执行失败/演示结果。

建议负责人：

- AI/Prompt 1 人
- 应用开发 1 人

### P1-2 会话与凭证安全

当前完成度：60%

当前状态：

- 后端仍使用内存 `_sessions`，但已加入 1 小时会话过期时间。
- 账户连接会写入 `connected_at`、`last_seen_at`、`expires_at`；过期会话会在单账户仓位、聚合仓位、风险扫描和执行凭证读取前被清理。
- 后端已提供 `DELETE /api/accounts/{platform}/disconnect`，主动断开会清理当前内存会话和凭证。
- `hedge` 执行链路已避免使用过期 session 中的来源仓位或实盘凭证。
- 浏览器端会持久化部分模型配置和账户非敏感状态。
- 私钥字段在前端持久化时会被清空，这是正确方向。
- 前端设置面板已增加“断开连接”，断开后会清空本地账户字段、私钥/API Secret 和仓位。
- 但后端敏感凭证仍存在内存中，缺少持久化会话存储、凭证保险箱、跨进程隔离和审计日志。

目标：

- 建立可控的会话机制，避免凭证泄露和状态丢失。

任务：

- [ ] 抽象 session service。
- [ ] 短期可用 SQLite/Redis 保存非敏感会话。
- [x] 敏感凭证只进入短期内存会话，前端持久化会清空敏感字段。
- [x] 增加会话过期时间。
- [x] 增加断开连接/清除凭证能力。
- [x] 前端断开连接后清理本地账户字段和仓位状态。
- [x] 风险扫描和 hedge 执行链路不再使用过期 session。

验收标准：

- [ ] 后端重启后行为可预期：当前为内存会话，重启后需要重新连接；后续应落 SQLite/Redis 非敏感会话。
- [x] 敏感信息不落 localStorage。
- [x] 用户能主动断开账户。
- [x] 会话过期后必须重新授权。
- [x] 过期 session 不会继续参与风险扫描或实盘凭证读取。
- [ ] 生产级审计日志和凭证保险箱。

建议负责人：

- 安全/基础设施负责人 1 人
